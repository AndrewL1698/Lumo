## Role
Naren owns the Parrot Chrome extension (Manifest V3). On sites the user has enabled, it swaps some English words on the page into Spanish, with the right article ("the house" → "la casa"). It shows a hover card with the meaning and pronunciation, and sends learning events to the backend. The extension has no site access by default and refuses never-list sites even if they are enabled. Naren also owns the eval and demo assets: the STT test sentences Andrew needs first, the ~50-sentence correction-accuracy set, the demo script, the backup video and the Devpost write-up.

## Rules that matter most here
- The service worker does every fetch, with `Authorization: Bearer <token>`. Content scripts only send messages.
- No host access by default. Sites are enabled from the popup via `chrome.permissions.request`, then `chrome.scripting.registerContentScripts`.
- Enforce the never-list in code even for allowlisted sites: email, chat, banking/payments/checkout, health/insurance, Docs/Canvas/Overleaf/GitHub, login and form pages.
- Never send full page text, URLs, history or typed input. `articleKey = hash(domain + title)`, e.g. a SHA-256 hex via `crypto.subtle`.
- Never block page load. Only replace spans inside one text node.

### 0.1 STT test sentences: `eval/sentences.json` (Andrew needs this first)
- 15 error-planted Latin American Spanish sentences plus **5 clean controls**. Each entry has `{ id, text, error_span, corrected_span, error_type }`.

  - `error_type` is one of the `SpokenErrorType` values: `conjugation`, `agreement`, `word_choice`, `word_order`, `missing_word`, `extra_word`. Weight toward `agreement` and `conjugation` (the demo uses an agreement error).

## Phase 2 → Sat ~4pm

### 2.1 Popup pairing
- The popup takes the 6-digit code and messages the SW. The SW sends `POST /api/pair` (`PairRequest` → `PairResponse`) and stores the token in `chrome.storage.local`.
- **Done when:** the token survives a browser restart, and every later fetch sends `Authorization: Bearer <token>`.

### 2.2 Real candidates + translate
- **Candidates:** the SW calls `GET /api/candidates` (`CandidatesResponse`, `Candidate`) and caches it using `generatedAt`.
- **Matching:** the content script tokenizes, looks up English forms in `wordindex.json` (form → lemmas), and scores matches with the specs §5.2 weights from the `Candidate` flags plus a little jitter. Aim for a 70% review/learning, 30% new mix. Karthik provides the flags; the extension applies the weights and the mix because only it knows what is on the page.
- **Translate:** send the chosen sentences in **one batch** per page: `POST /api/translate` (`TranslateRequest` → `TranslateResponse`, items `TranslateItem`). Results come back in request order. For `null`, skip the word. Otherwise replace the exact `span` (it includes the determiner, e.g. "the strike") with `replacement` ("la huelga") inside that text node. Keep the original English for the hover card.
- **Done when:** on the demo site, swaps come from real data, and only after the batch returns.

### 2.3 Hover card
- Shows the Spanish with its article, the English (the original span you replaced), "Knew it" / "Didn't know", and a false-friend fun fact when the word is flagged (agree the data source with Karthik, e.g. a `falseFriends` list in `wordindex.json`).
- A hover counts only after 500 ms.
- **Done when:** a quick mouse pass sends nothing; a 500 ms hover sends one `hover` event.

### 2.4 Batched event queue (in the SW)
- **Schemas:** `ExtensionEvent`, `ExtensionEventType`, `EventsRequest` → `EventsResponse`.
- `id = crypto.randomUUID()`, `ts` = epoch ms, `articleKey` = hash(domain + title).
- **`hover` events carry `meta.sentence`**, the sentence the word appeared in (agreed; Andrew's tutor uses it).
- `knew_it` / `didnt_know` come from the card buttons. Send one `reading` event per page with `meta.title` and `meta.domain`.
- Flush every ~5 s or 20 events. On failure, retry with the **same ids**. Keep the queue in `chrome.storage` (MV3 kills idle service workers).
- **Done when (Phase 2 exit, with Karthik):** hovering a swapped word writes an `events` row with `meta.sentence` and updates `user_words`.

## Starter sites and new-site nudge (from Andrew, D-021)
Onboarding now saves a list of reading sites to `settings.allowlist` (16 starter sites, all checked by default; the list is `READING_SITES` in `shared/src/readingSites.ts`). The web app can't grant access, so the extension needs to. About 1 to 1.5 h. Cut order: after the never-cut items; part 2 is the first to drop.

1. **Popup: "Turn on your sites"** (`src/popup/index.ts`, `popup.html`).
   - `pending` = `settings.allowlist` (from `GET_SETTINGS`, which already reads `/api/settings` fresh) minus `enabledOrigins` (from `GET_STATUS`) minus anything `neverListReason()` blocks.
   - Show the button only when paired and `pending.length > 0`: "Turn on your N sites".
   - In the click handler, call `chrome.permissions.request({ origins: pending.map((o) => o + "/*") })` **synchronously** (user gesture), the same pattern as the "Always on for this site" button. Chrome shows one prompt listing all of them.
   - On `true`, send `ENABLE_SITE` for each origin (existing `enableSite` in `src/sw/index.ts`) and show "N sites on. Reload a page to start."
2. **Icon dot on good sites that aren't on yet** (`src/sw/index.ts`, `manifest.json`).
   - Add the `"declarativeContent"` permission. It has no install warning and the extension never sees the URL: Chrome does the matching.
   - On `onInstalled`, `onStartup` and after each `ENABLE_SITE`: `chrome.declarativeContent.onPageChanged.removeRules(undefined, () => addRules([rule]))`, one rule whose `conditions` are a `new chrome.declarativeContent.PageStateMatcher({ pageUrl: { schemes: ["https"], hostEquals: host } })` per `READING_SITES` host not in `enabledOrigins`, and whose action is `new chrome.declarativeContent.SetIcon({ imageData })`.
   - Build `imageData` in the service worker: `fetch(chrome.runtime.getURL("icons/icon32.png"))` → `createImageBitmap` → draw on an `OffscreenCanvas` with a small amber dot in a corner → `getImageData` (do 16 and 32).
   - Test `SetIcon` first: if it misbehaves, skip the dot and ship only part 3.
3. **Popup card on a suggested site.** The popup already reads the tab origin (`activeTab`). If that origin is in `READING_SITES` and not enabled, the "Always on for this site" area reads "Luci reads well on {name}. Turn it on here?"
4. Import `READING_SITES` from `@parrot/shared` (`readingSites.ts` has no zod).
5. Privacy check (non-negotiable 4): no new permissions with a warning, no URLs read or sent, never-list still checked in `enableSite`.
